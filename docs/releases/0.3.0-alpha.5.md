# ProductOS 0.3.0-alpha.5

**Date:** 2026-10-05

## Outcome

ProductOS can execute a declared behavioral pilot in addition to exporting cases and reporting
assessments. The adapter freezes the supplied instructions and cases, isolates generation from
judging, and preserves the artifacts needed to inspect an observed run.

## Delivered

- Schema-validated execution configuration with explicit model, identities, reasoning effort,
  service tier, timeout, instruction paths, and repetition count.
- One fresh, ephemeral, read-only Codex context per generation and judgment; tool activity
  rejects a call under this supplied-instruction pilot protocol.
- Frozen instruction bundle, rubric, prompts, packets, configuration, and runner; base commit,
  dirty-worktree state, CLI version, and file SHA-256 recorded in the eval run.
- Responses preserved in checkpoints and assessment records, with dimension evidence and every
  expected, forbidden, and hard-failure behavior assessed independently.
- Resume checks for changed snapshots, configuration, runner identity, executor metadata, and
  response checkpoints; completed work is reused without another model call.
- Repository validation of archived pilot file hashes and verbatim response provenance.
- Preparation checkpoints with zero assessments are valid only while `partial`; full completed
  coverage is still enforced semantically.

## Qualification boundary

The [first observed pilot](../../evals/baselines/seed-pilot-2026-10-05/README.md) completed all
21 cases and recorded 88.6% expected behavior coverage, zero judged hard failures or forbidden
behavior violations, and a critical average of 3.68/4. The maximum multilingual difference was
one point against a 0.5-point gate: the pilot failed that gate and remains release ineligible.
These numbers describe uncalibrated automated assessments, not established system quality.

A [separate interface exploration](../design/interface-options.md) compares terminal, local
browser, and desktop concepts. It does not select or implement a product runtime.

## Verification

The offline suite passes 76 tests. Repository validation passes 22 schemas and 42 fixtures,
including archived file hashes and response provenance. Lint, index freshness, and source
freshness checks pass. The pilot's deterministic gate-enforcing report intentionally returns
exit code 2 for the multilingual failure; model calls remain outside CI.

## Remaining qualification work

The seed configuration uses one repetition and the same model for generation and judging in
separate contexts. Its judge remains `pilot`. Human calibration, at least three repetitions
during stochastic calibration, independent editorial review, and runtime skill-discovery tests
remain required before stable release. The supplied instruction bundle does not test progressive
reference loading or retrieval, and there is no unskilled-model control for an improvement claim.

Model execution is opt-in and excluded from CI. Offline tests use labeled synthetic outputs to
check implementation paths; they are separate from observed behavioral responses.
