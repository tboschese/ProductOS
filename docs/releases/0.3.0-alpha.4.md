# ProductOS 0.3.0-alpha.4

**Date:** 2026-10-05

## Outcome

The documented generator command previously exported each complete eval case, including the
criteria it was meant to be evaluated against. It now produces a blind packet. Reviewers get
a separate snapshot so scoring can use the same cases and thresholds after the repository
changes.

## Delivered

- `--export` emits only case ID, locale, input, and context through an explicit allowlist.
- `--export-review` emits full cases and suite policy for reviewers only.
- A new packet schema and fixtures enforce the audience boundary; both exports are validated
  before writing and shared output paths are rejected.
- `evaluate_results --review-packet` checks snapshot consistency, evaluates against its cases
  and policy, and records the exact file SHA-256 in JSON and text summaries.
- Regression tests verify that rubric fields and future metadata stay out of generator exports,
  generator packets cannot be used for scoring, and later repository case or policy edits do
  not alter snapshot-based evaluation.
- Source records now declare contract version `0.3.1` for required freshness metadata. The
  canonical records and valid fixture were migrated; verification dates and review status
  remain unchanged.

## Migration

Consumers that used `--export` to inspect judging criteria must switch to `--export-review`.
Regenerate old generator packets: earlier exports included judging criteria. These should not
be used for blind generation. Keep the reviewer packet with the raw responses and pass it to
`--review-packet`; `--suite` remains available for evaluation against live repository data.

Older source records must set `schema_version: 0.3.1` and provide temporal stability and a
review interval. Package versions and individual artifact contract versions are independent.

## Verification boundary

Repository validation passed for 21 schemas and 40 fixtures. All 55 tests and Ruff checks
passed, with no whitespace errors. Both packet exports were exercised for the 21 seed cases
(13 English, four Spanish, four Brazilian Portuguese). The knowledge index was rebuilt and
checked without changes, and source freshness and deterministic duplicate checks passed.

Automated tests use synthetic assessments to verify reporting and failure paths. They do not
establish Staff PM behavior quality. No real baseline, calibrated judge, independent editorial
review, or stable release is claimed by this increment.

Packet exports freeze case data and policy, not skill instructions or generator execution. The
executor must use a fresh context per case and preserve the rest of the run configuration as
specified in the [judge protocol](../../evals/judge-protocol.md).
